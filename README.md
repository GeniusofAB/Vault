# Vault

Статический каталог модов для Dota 2. Никакого бэкенда — обычный
GitHub Pages сайт: html/css/js плюс сами файлы модов лежат в репозитории.

## Структура

```
index.html
style.css
script.js
mods.js              # категории + список id модов
mods/
  <id>.vpk            # сам мод
  <id>.json           # его метаданные
pic/
  <id>.png             # превью карточки (необязательно)
```

## Как добавить мод

1. Положить файл `mods/<id>.vpk`.
2. Рядом положить `mods/<id>.json`:

```json
{
  "title": "Название",
  "author": "Автор",
  "category": "hud",
  "tags": ["тег1", "тег2"],
  "description": "Описание.",
  "fileSizeMB": 6.8,
  "dateAdded": "2026-07-24",
  "downloads": 0,
  "previewColor": "#8C5CF5"
}
```

3. Не обязательно: положить `pic/<id>.png` — превью карточки. Если файла
   нет, покажется цветная заглушка (`previewColor`) с иконкой категории.
4. Добавить `"<id>"` в массив `modIds` в `mods.js`.

`category` должен совпадать с одним из `id` в `categories` (тоже в `mods.js`).

id — это просто имя файлов без расширения, например для
`mods/pak99_dir.vpk` id будет `pak99_dir`.

## Почему список id держим в mods.js, а не читаем папку

GitHub Pages отдаёт чистую статику без листинга директорий — скрипт со
стороны браузера не может сам узнать, что лежит в `mods/`. Поэтому список
id — единственное, что приходится обновлять руками при добавлении мода
(кроме самих файлов).

## На что обратить внимание, раз файлы теперь в репозитории

- Жёсткий лимит на один файл в git — 100 МБ (Git его просто не пустит без
  Git LFS).
- GitHub официально не рекомендует раздувать репозитории Pages сильно
  больше ~1 ГБ и не позиционирует Pages как хостинг для больших
  бинарников — банить за это не будут, но это мягкий лимит, о котором
  стоит помнить.

Если конкретный мод крупнее — либо Git LFS, либо старый вариант с внешним
хостингом (GitHub Releases, до 2 ГБ на файл).
